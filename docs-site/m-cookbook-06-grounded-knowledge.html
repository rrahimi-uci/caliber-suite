Cookbook 06 · Build

Grounded Knowledge Assistant

A policy assistant you can measure: cited chunks, retrieval modes compared, calibration that lifts Recall@1, and low-confidence runs sent to review.

BuildCore120–180 min
What you build. A retrieval assistant over 11 company policies (5,100 words): a policy-corpus bucket, a knowledge base policy-qa-kb built as two versions (1,400- and 500-character chunks), retrieval calibrated on 41 questions, and an installed knowledge_rag workflow bound to it. A top-1 similarity gate marks outside-the-corpus questions needs_review and a review queue receives them. Storage, chunking, embeddings and ranking are real; answer text and model-judged scores are simulated by default.
Surfaces: Object Store Knowledge Bases Prompts Workflows Cookbooks Observability Review Queues Evaluations
What you learn
  • Upload 11 policies to the object store and build knowledge base version 1 (a queued job a worker runs): 11 sources, 27 chunks, 384-dimension vectors
  • Ask in Dense, Hybrid and GraphRAG and check that the cited chunk holds the clause (365 days)
  • Import 41 calibration questions and run Calibrate (Recall@k, nDCG@k), set a baseline and compare modes
  • Build the tuned version 2 (69 chunks), Set active to switch versions and roll back
  • Meet real build failures: no object store, no embedding libraries, an unreadable file (build completes with failed_sources: 1), nothing readable (build fails)
  • Install the cookbook workflow, run it, and enqueue the low-confidence run in a Review Queue

Developer notes & gotchas
  • Flag. CALIBER_FEATURE_COOKBOOKS=true and nothing else (no Aria, no integrations). Knowledge needs more than the base install: an S3-compatible store, pip install "caliber-suite[knowledge,knowledge-local]" and the all-MiniLM-L6-v2 model (about 90 MB). Start with HF_HUB_OFFLINE=1 scripts/cookbook-env.sh up lab06 --flags cookbooks --s3.
  • Real: object store, queue and worker, chunking, embeddings, ranking, Recall@k, nDCG@k, the score gate, activation and rollback. Simulated (default fake LLM/eval providers): answer text is an extractive digest, Faithfulness and Answer-correctness are blank (—), and Evaluations refuses scoring with 400 evaluation requires a real LLM provider.
  • No decision is produced on a simulated stack. The kb-answer prompt and the CitationFaithfulness judge are stored for real, but answer, abstain or clarify and the 0.90 faithfulness target need a real model. The lab verifies the evidence (both conflicting refund documents are retrieved together) and what retrieval alone can refuse.
  • The gate has a limit. 0.42 is tuned on this question set. It cannot refuse the 2 trap questions (Enterprise terms), whose policy exists but whose clause does not (scores 0.56 and 0.66); that needs a model and the review queue. Re-derive the gate from your own scores.
  • Retrieval always returns chunks. The dress-code question still returns nearest chunks; refusing is a decision on top. graph_hybrid is worse here (35/41), and hybrid helps the 1,400-character chunks but hurts the 500-character ones, which is why you calibrate.
  • Build behavior. A finished build activates itself, even with an unreadable file, so read failed_sources. AGE retrieval is not used (pgvector and Apache AGE are off). The first build can sit queued for minutes without HF_HUB_OFFLINE=1.
  • Runnable. sdk/caliber-sdk/examples/cookbooks/cookbook_06_grounded_knowledge_assistant.py (about a minute, 51 ok lines) and caliber/caliber-ui/e2e/cookbooks/labs/06-knowledge-retrieval.spec.ts; environment: scripts/cookbook-env.sh up lab06.
