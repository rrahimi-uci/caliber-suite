Aria: Human-Review Queue from Intent

One sentence → Aria plans and creates a review queue with a safety / citation / tone label schema.

Aria — AutonomousAria15–25 min
What you build. Aria decomposes a review-governance intent into review_queue.create (+ add_items); you enter the queue's question schema in the plan's input form and approve.
Surfaces: Plans Review Queues Observability
What you learn
  • Plan a governance queue from one intent
  • Design a review question schema (pass_fail / categorical / numeric / text)
  • See why “review queue” proposes two steps
  • Enter the queue's schema in the plan's input form
  • Skip the enqueue step when there are no traces yet

Implementation flow

flowchart LR
  I[/"Intent: review queue for safety, citation, tone"/] --> PL[Aria Plans]
  PL --> S1[step: review_queue.create]
  PL --> S2[step: review_queue.add_items]
  S1 -.input form + approve.-> RQ[Review Queues: agent-reply-review]
  S2 -.Skip step if no traces.-> SK[skip]

  1. Integrations and preview › Plans
    Before you start: set CALIBER_FEATURE_ARIA=true on the CALIBER server and restart it; Aria and the Plans page are off by default. In the left sidebar, under the Integrations and preview group (the page carries a Preview badge), click Plans. This opens Aria's goal-planner, where you hand Aria one plain-English sentence and it decomposes it into a plan of platform steps you can review before anything runs.
    You'll see: The Aria Plans page with a Goal text box, an Autonomy dropdown, a Decompose goal button, and a table of existing plans below.

Then open the Autonomy dropdown and choose Stop before each change (this is the ask_each level — Aria pauses for your OK before every step that changes anything).

    AutonomyStop before each change (= ask_each)

    Step 2review_queue.add_items — tier mutate (same domain, so it is proposed too)

    Approve the shape of the plan (you are signing off on which steps Aria will run, not running them yet). Click Approve plan in the top-right of the plan header.
    Click Approve plan
    You'll see: The status badge flips from DRAFT to APPROVED, and an Execute button appears in the header.

    Start running the plan. Click Execute. Aria reaches the first step, review_queue.create, but the planner could not know your queue's name or question schema, so it pauses on a violet Aria needs information form with a field per capability input (name and questions are required) and two buttons, Continue plan and Skip step.
    Click Execute
    You'll see: The review_queue.create row shows WAITING INPUT and an Aria needs information form is open above the step list.

    You'll see: After Approve, the review_queue.create row shows DONE and the plan moves on to review_queue.add_items.

  7. Integrations and preview › Plans › PLAN-… (input form) creates · Plan completed (queue created, enqueue skipped)
    Handle the second step, review_queue.add_items. The planner already linked its queue_id to the queue the previous step created, so the form only asks for trace ids (plus optional experiment id and assignee). You have no flagged traces yet (this scenario is queue-first), so click Skip step. (With real flagged ids you would paste them as a JSON array — see enqueue.json — click Continue plan, then Approve.)
    Click Skip step
    You'll see: The review_queue.add_items row shows SKIPPED and the plan finishes with status COMPLETED (create done, add_items skipped).

    Verify the queue is live and reviewable. Under Operate, click Review Queues, then click the agent-reply-review name to open it. When you have flagged traces, paste their ids into the Add traces to review box and click Enqueue (optional spec: enqueue.json).

assets/intent.md 
# The intent you give Aria

## Canonical (works with the default HeuristicPlanner)

> Set up a review queue for human labeling of agent replies for safety, citation, and tone.

Why this wording: the default planner proposes a step for each capability whose
**domain word** appears in the goal. The phrase **"review queue"** maps to
**both** `review_queue.create` **and** `review_queue.add_items` (same domain).
Keep the literal phrase "review queue" in the sentence.

Autonomy: **Stop before each change** (`ask_each`: an **Approve** / **Deny** prompt before every mutate step, after the input form).

## Natural-language variant (not understood by the default planner)

> Stand up human grading of our agent's answers for safety, citations, and tone.

Reads better, but the default heuristic planner has no mapping from "human
grading" to `review_queue.create` and would plan no steps. Use the canonical
wording.

## Note on the second step

Because "review queue" also triggers `review_queue.add_items`, Aria will pause to
enqueue traces (its form only asks for `trace_ids`; `queue_id` is linked from the
create step). If you have no flagged traces yet, click **Skip step** — the queue
is still created and you enqueue later.

Developer notes & gotchas
  • Feature flags. CALIBER_FEATURE_COOKBOOKS=true opens the gallery and CALIBER_FEATURE_ARIA=true opens Plans; both are off by default.
  • “review queue” triggers both review_queue.create and review_queue.add_items; click Skip step on the second if you have no traces.
  • Question item fields: key, title, type, options, required, target (feedback|expectation).
  • The planner leaves the queue's name and questions empty; the plan's input form collects them (see ARIA-AUTONOMY.md).
