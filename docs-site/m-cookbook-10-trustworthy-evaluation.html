Cookbook 10 · Govern

Trustworthy Evaluation

Certify that an automated judge agrees with human reviewers before it is trusted to block a release.

GovernCore60–120 min
What you build. A governance lane that loads a 50-row test set of support replies and incident summaries, defines a custom FaithfulnessJudge, scores a baseline and a candidate with deterministic graders plus the judge, then has people review the same outputs and imports their labels so CALIBER computes agreement, Cohen's kappa and false positives and negatives. The judge is certified only if it clears the thresholds on enough rows, otherwise rejected, and every disagreement goes back into the test set as a hard case.
Surfaces: Prompts Test Sets Judges Evaluations Review Queues
What you learn
  • Load a 50-row test set (Prompts > Calibration > Upload JSON/JSONL); each appended example is a version, so 50 rows is version 51
  • Create a judge whose instructions use only {{ inputs }}, {{ outputs }}, {{ expectations }}, {{ conversation }} or {{ trace }}; {{ evidence }} is refused with a 400
  • Run baseline and candidate Evaluations with Contains expected, Non-empty and the judge, and compare per-row results
  • Review the same traces in a queue, then Import labels and Check alignment in Judges > Try it > Human alignment
  • Certify or reject on agreement, kappa and a minimum row count, using a deliberately weak LenientJudge as the negative control
  • Feed the nine disagreements back into the test set (tag judge-disagreement)

Implementation flow

assets/seed_traces.py 
#!/usr/bin/env python3
"""Record the 50 dataset outputs as MLflow traces, so they can be reviewed in CALIBER.

In a real deployment these traces are produced by your application (SCN-07 support replies and
SCN-08 incident summaries). A fresh checkout has none, and Operate > Review Queues works on traces,
so this script writes one trace per dataset row: the request is the row's ``input`` and the response
is its recorded output text. Each trace carries the tag ``cookbook10.row`` (J01..J50).

Needs the ``mlflow`` package and ``MLFLOW_TRACKING_URI`` (the MLflow server CALIBER uses).
Prints a JSON map ``{"J01": "<trace_id>", ...}`` on stdout. Every run writes 50 new traces, so run it
once per environment.

    MLFLOW_TRACKING_URI=http://127.0.0.1:5000 \
      python docs-site/cookbooks/10-judge-certification-human-review-lab/assets/seed_traces.py > traces.json
"""

from __future__ import annotations

import json
import sys
from pathlib import Path

DATASET = Path(__file__).resolve().parent / "dataset" / "aggregated-outputs.jsonl"
EXPERIMENT = "cookbook-10-judge-certification"


def output_text(row: dict) -> str:
    """The text of a recorded output: the support reply or the incident summary."""
    return row["outputs"].get("reply") or row["outputs"].get("summary") or ""


def seed(dataset: Path = DATASET) -> dict[str, str]:
    """Write one trace per dataset row and return ``{row id: trace id}``."""
    import mlflow

    mlflow.set_experiment(EXPERIMENT)
    trace_ids: dict[str, str] = {}
    for line in dataset.read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        row = json.loads(line)
        with mlflow.start_span(name="recorded-output", span_type="CHAIN") as span:
            span.set_inputs(row["input"])
            span.set_outputs(output_text(row))
            trace_id = span.trace_id
        mlflow.set_trace_tag(trace_id, "cookbook10.row", row["id"])
        trace_ids[row["id"]] = trace_id
    mlflow.flush_trace_async_logging()

# Alignment worksheet: the arithmetic, by hand

CALIBER computes judge-versus-human alignment in the product (Judges > Try it > **Human alignment**
> **Import labels** > **Check alignment**, or `POST /judges/{id}/alignment`). The product's job is to
run the judge on each labelled row. Everything after that is arithmetic over two columns of
pass/fail verdicts, and this worksheet shows it so you can check the readout yourself, or any other
judge's.

[`expected-alignment.csv`](expected-alignment.csv) holds both columns for the 50-row dataset:
`human_label` (the reviewer's verdict, from the dataset file) and `stand_in_strict_judge` (what the
lab's scripted stand-in model answers for `FaithfulnessJudge`). With a real model the judge column
is yours to read off the **Evaluations** per-row results or the alignment response's `per_example`.

## 1. Tally the 2x2

Treat the judge's *pass* as the positive class.

|                | human pass | human fail |
| -------------- | ---------- | ---------- |
| **judge pass** | TP = 23    | FP = 5     |
| **judge fail** | FN = 4     | TN = 18    |

- **FP** (judge pass, human fail): the judge waved through something a person rejected. These are
  the dangerous ones for a release gate: J03, J12, J19, J24, J33.
- **FN** (judge fail, human pass): the judge blocked something a person accepted: J14, J17, J22, J30.

## 2. Agreement and kappa

```text
n   = 23 + 5 + 18 + 4                      = 50
p_o = (TP + TN) / n  = (23 + 18) / 50      = 0.82            (observed agreement)

judge says pass:  (23 + 5) / 50 = 0.56     human says pass:  (23 + 4) / 50 = 0.54
judge says fail:  (4 + 18) / 50 = 0.44     human says fail:  (5 + 18) / 50 = 0.46

p_e = 0.56 × 0.54 + 0.44 × 0.46            = 0.3024 + 0.2024 = 0.5048   (agreement expected by chance)
kappa = (p_o - p_e) / (1 - p_e)            = (0.82 - 0.5048) / 0.4952   = 0.6365
```

The product reports `agreement_rate` 0.82 and `cohen_kappa` 0.6365 (the Judges page shows 82% and
0.64). Kappa matters more than agreement: a judge that says "pass" to everything would agree with a
mostly-passing sample and measure nothing.

## 3. The certification rule used in this lab

A judge is **certified** only when all three hold, otherwise it is **rejected** (or **not
certifiable** if the sample is too small to say):

| Check | Threshold | Why |
| --- | --- | --- |
| labelled rows scored | all of them, and at least 30 | a row the judge errored on is left out of the numbers; five rows can clear both bars by luck (below) |
| agreement | 0.80 or more | the lab's gate (`verification.yaml`) |
| Cohen's kappa | 0.60 or more | agreement alone is inflated by a skewed sample |

`FaithfulnessJudge` with the stand-in: 50 of 50 scored, agreement 0.82, kappa 0.6365: **certified**.

A weak judge, for contrast (`LenientJudge`, which passes anything that is not empty or cut off):
TP 27, FP 21, TN 2, FN 0. Agreement (27 + 2) / 50 = 0.58, kappa = (0.58 - 0.5368) / 0.4632 = 0.0933:
**rejected**. It never fails a wrong answer, so it agrees with the humans barely more than chance.

## 4. Why thirty rows

The first five rows (J01 to J05) give judge `[pass, fail, pass, fail, pass]` against human
`[pass, fail, fail, fail, pass]`: agreement 4/5 = 0.80 and kappa = (0.8 - 0.48) / 0.52 = 0.6154. Both
bars cleared on five rows, and the product returns those numbers without complaint. The 50-row
numbers are 0.82 and 0.6365, so here the small sample happened to land near the truth; it would not
always. Insist on a sample large enough to include the hard cases.

## 5. The ten rows of the UI path

The UI path has a person review ten traces (J01, J02, J03, J04, J05, J08, J09, J11, J14, J26):
TP 4, FP 1 (J03), TN 4, FN 1 (J14). p_o = 8/10 = 0.80, p_e = 0.5 × 0.5 + 0.5 × 0.5 = 0.50, kappa =
(0.80 - 0.50) / 0.50 = 0.60. The Judges page shows **Agreement 80%**, **Cohen's κ 0.60**, **FP 1 ·
FN 1**, over 10/10 examples. That meets both numeric bars but not the 30-row minimum: a readout, not
a certification. `LenientJudge` on the same ten rows: TP 5, FP 4, TN 1, FN 0, agreement 60%, kappa
0.20.

## 6. What to do with a disagreement

Every row with `agree = NO` is a calibration input, not noise:

1. Read the reviewer's reason (`human_label_reason` in the dataset file) and the judge's rationale.
2. Decide which side is wrong. A row the judge misses because its rubric never mentions it (J03,
   J12, J19, J24, J33: unsupported claims with no figures in them) is a rubric gap: reword the
   instructions. A row a person would accept but the judge fails on formatting (J14, J17, J22, J30:
   a derived or reformatted figure) is a rubric ambiguity: say whether derivations are allowed.
3. Add the row back to the test set as a hard case (`POST /eval-datasets/{id}/examples/from-trace`
   with `expected` overridden to the evidence, tag `judge-disagreement`) so every later run sees it.
4. Re-run the Evaluations scorecard and the alignment check. Do not certify until it clears.

One trap when you label through a Review Queue: **Import labels** passes every answer on the queue
item other than the pass/fail one to the judge as `{{ expectations }}`. Keep those answers to the
evidence. A reviewer's explanation that quotes the unsupported claim becomes "evidence" the judge
then agrees with: with the stand-in, putting `human_label_reason` into the item drops agreement
from 0.82 to 0.66 (FP 5 to 13) and kappa from 0.6365 to 0.2952.

Developer notes & gotchas
  • Feature flag. CALIBER_FEATURE_COOKBOOKS=true opens the gallery card and the SDK script's recipe check; the lab itself uses only test sets, judges, evaluations and review queues. Start a stack with scripts/cookbook-env.sh up lab10 --flags cookbooks.
  • Simulated default cannot run the judge. With CALIBER_LLM_PROVIDER=fake and CALIBER_EVAL_PROVIDER=fake, Evaluations answer 400 and alignment reports every row as an error (scored 0 of 50). Nothing is faked; use a real provider or the lab's stand-in model (CALIBER_EVAL_PROVIDER=mlflow with a real LLM provider, or the server refuses to start).
  • The stand-in model proves wiring and arithmetic, not judge quality. It is a scripted OpenAI-compatible server (assets/stand-in-model/stand_in_model_server.py); its numbers (FaithfulnessJudge 0.82 and kappa 0.6365 over 50 rows) say nothing about how a real model would judge this data.
  • Calibration gate on a canned score. On the simulated stack the calibration job on the same test set passes its gate on a canned 0.94 (simulated: true); that verdict means nothing without a judge you have already checked against people.
  • Only five rows can give agreement 0.8 and kappa 0.6154: the product returns numbers for any sample of 1 to 100 rows, so the lab's rule of 30 scored rows is what makes certification meaningful. The UI path over 10 rows is a readout, not a certification.
  • Keep reviewer notes out of the queue. Import labels passes every non-pass/fail answer to the judge as {{ expectations }}, so a reviewer's quote of the unsupported claim lowers agreement (0.82 to 0.66); keep the evidence box to evidence.
  • Run it through the API with sdk/caliber-sdk/examples/cookbooks/cookbook_10_trustworthy_evaluation.py (add --expect-stand-in to pin the numbers), or the Playwright spec caliber/caliber-ui/e2e/cookbooks/labs/10-judge-certification.spec.ts.
