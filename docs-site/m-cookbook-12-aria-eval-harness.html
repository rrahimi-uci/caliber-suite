Aria: Evaluation Harness from Intent

One sentence → Aria plans and creates a faithfulness judge + a test set; you fill the judge's fields and approve.

Aria — AutonomousAria15–25 min
What you build. Give Aria a one-line intent; it decomposes the plan (judge.create + eval_dataset.create) in the Plans page. You approve the plan, fill the judge's fields in the plan's input form, and approve each step.
Surfaces: Plans Judges Test Sets Evaluations
What you learn
  • Use the Plans page to turn an intent into a capability plan
  • Read Aria's plan + autonomy dial
  • Understand the planner needles (domain words)
  • Fill a step's inputs in the plan's “Aria needs information” form
  • See how step names are linked between steps

Step-by-step UI only

Each step shows the exact navigation path, the fields to fill, the button to click, and a snapshot of the CALIBER screen you'll be on.

  1. Integrations and preview › Plans creates · Aria Plans page open
    Before you start: set CALIBER_FEATURE_ARIA=true on the CALIBER server and restart it; Aria and the Plans page are off by default. Open Aria's planner. Click Plans in the left sidebar (under the Integrations and preview group; the page carries a Preview badge). This opens the Aria Plans page, where you hand Aria a one-line goal and it decomposes it into platform steps you approve before anything runs.
    You'll see: The Aria Plans page with a Goal textarea, an Autonomy selector, and a Decompose goal button.
    Screen snapshot
  2. Integrations and preview › Plans › Goal creates · Draft Aria plan intent.md ↓
    State the intent. Paste the canonical one-line intent from intent.md into the Goal field. The exact wording matters: the default planner keys off the literal domain words judge and eval dataset, so keep both in the sentence (it also recognises "test set" for the dataset step, but a phrase like "faithfulness scoring" would not produce a judge step). Set Autonomy to Stop before each change (this is the ask_each level) so Aria asks you to approve every mutate step.
    Fill in
    GoalCreate a judge for answer faithfulness and an eval dataset to run it on.
    AutonomyStop before each change (ask_each)
    Click Decompose goal
    You'll see: A draft plan appears below the form.
    Screen snapshot
  3. Integrations and preview › Plans › (draft plan) creates · Reviewed plan (2 steps) expected-plan.json ↓
    Review the decomposed plan. Confirm Aria produced exactly two steps from the one sentence — judge.create and eval_dataset.create — matching expected-plan.json. This decomposition is the autonomous-orchestration showcase: one intent in, the right governed steps out.
    You'll see: The draft plan lists two mutate steps: judge.create and eval_dataset.create.
    Screen snapshot
  4. Integrations and preview › Plans › (draft plan) creates · Approved plan
    Approve the plan shape. With the plan in draft status, click Approve plan. This records that you accept the orchestration before any step runs.
    Click Approve plan
    You'll see: The plan moves to approved status and an Execute button appears.
    Screen snapshot
  5. Integrations and preview › Plans › (approved plan) creates · Plan running, paused at the judge.create input form
    Execute the plan. Click Execute. Aria reaches the first step, judge.create, but the planner could not know the judge's name or instructions, so it pauses on a violet Aria needs information form: "Provide the required inputs for step 1: Create judge." with a field per capability input (name and instructions are marked required) and two buttons, Continue plan and Skip step.
    Click Execute
    You'll see: The plan pauses on the judge.create step (WAITING INPUT) with an Aria needs information form.
    Screen snapshot
  6. Integrations and preview › Plans › (input form) creates · Judge inputs entered answer-faithfulness.judge.json ↓
    Fill the form with the judge spec from answer-faithfulness.judge.json — these are the judge.create inputs. The instructions must reference {{ inputs }} / {{ outputs }} / {{ expectations }} (at least one is required); set feedback value type to bool. Click Continue plan: Aria merges and validates the inputs (a bad value is rejected and the form stays open), then — because autonomy is ask_each — raises an Aria needs your approval prompt, "Approve step 1: Create judge (judge.create)?".
    Fill in
    nameAnswerFaithfulness
    feedback value typebool
    instructionsYou audit whether an assistant answer is faithful to its evidence. You are given the request {{ inputs }}, the model {{ outputs }}, and the reference {{ expectations }}.

    Return true ONLY if every factual claim in {{ outputs }} is supported by {{ expectations }} (or by evidence cited in {{ inputs }}), and the answer makes no unsupported commitments. If any claim is unsupported, contradicted, or hallucinated, return false. Judge faithfulness only — not style.
    model (optional)your configured judge model (e.g. the gateway default)
    Click Continue plan
    You'll see: The form closes and a pending Approve / Deny prompt for judge.create appears.
    Screen snapshot
  7. Integrations and preview › Plans › (interaction prompt) creates · Plan completed (judge + test set created by Aria)
    Click Approve — Aria runs judge.create and the plan moves on to eval_dataset.create. That step has nothing to ask: the planner linked its name to the judge step's name, so it raises only an Approve / Deny prompt. Click Approve again; Aria creates an empty versioned test set (named AnswerFaithfulness, taken from the judge step) and the plan reaches completed. (Deny would mark a step skipped instead.)
    Click Approve
    You'll see: Both steps show DONE and the plan status is COMPLETED.
    Screen snapshot
  8. Also in the alpha › Judges + Core journey › Test Sets + Integrations and preview › Plans creates · Verified judge + test set + completed plan support-faithfulness.dataset.json ↓
    Verify the end-to-end result. Confirm three things: Judges shows AnswerFaithfulness active with Returns = bool; Test Sets shows an empty test set AnswerFaithfulness at version 1; and the Plans page shows the plan completed with both steps done. Together these prove Aria turned one sentence into a governed two-step plan and created the two real artifacts. (For a separately named set, create one on Test Sets from support-faithfulness.dataset.json.)
    You'll see: An active judge, a real test set, and a completed two-step plan — the scenario gate.
    Screen snapshot
  9. Operate › Observability + Core journey › Evaluations creates · (follow-up) Scored run + AnswerFaithfulness judge verdicts using the Aria-built harness
    (Follow-up) Put the harness to work. Add example rows to the new AnswerFaithfulness test set — either author them in the row editor at /eval-datasets/:id → + Add example, or in Observability open a trace, use its Add to test set panel, pick the test set under Choose test set, and click Add example (or reuse a starter dataset such as cookbooks/01-prompt-regression-lab/assets/dataset/). Then go to Evaluations, click Run evaluation, pick the test set, tick the built-in Graders, and tick your AnswerFaithfulness judge under Custom LLM judges so it runs as a Judge.<id> scorer for an automatic per-row verdict. This is the same scored-run loop as SCN-01 / SCN-10 and needs a real model provider — the default evaluator and LLM are fake, and Run evaluation returns a 400 without one.
    Fill in
    Test setAnswerFaithfulness (the test set Aria created)
    Gradersbuilt-in scorers (Contains expected, Token F1, Non-empty) + AnswerFaithfulness under Custom LLM judges
    Click Run
    You'll see: A scorecard run grades the rows on the deterministic scorers plus the AnswerFaithfulness judge column, closing the loop from one intent to a running evaluation harness.

assets/intent.md 
# The intent you give Aria

## Canonical (works with the default HeuristicPlanner)

> Create a judge for answer faithfulness and an eval dataset to run it on.

Why this wording: the default planner proposes a step for each capability whose
**domain word** appears in the goal. "judge" → `judge.create`; "eval dataset" →
`eval_dataset.create`. Keep both literal needles in the sentence.

Autonomy: **Stop before each change** (`ask_each`: an **Approve** / **Deny** prompt before every mutate step, after the input form).

## Natural-language variant (only partly understood)

> Set up faithfulness scoring for our support answers, with a test set to run it on.

This reads better, but the default heuristic planner recognises "test set"
(→ `eval_dataset.create`) and not "faithfulness scoring" (a judge step needs the
literal word "judge"), so it plans only the test-set step. Use the canonical
wording.
assets/expected-plan.json 
{
  "goal": "Create a judge for answer faithfulness and an eval dataset to run it on.",
  "autonomy": "ask_each",
  "expected_steps": [
    {
      "capability_key": "judge.create",
      "tier": "mutate",
      "interaction": "input form (Aria needs information): enter the judge fields from judges/answer-faithfulness.judge.json, then Approve"
    },
    {
      "capability_key": "eval_dataset.create",
      "tier": "mutate",
      "interaction": "no input form: name is linked from judge.create (the set is created as AnswerFaithfulness); just Approve"
    }
  ],
  "notes": "Step order follows registry order; the planner links eval_dataset.create's name to judge.create's name (depends_on = [judge.create]). judge.create raises an input interaction for its missing fields; under autonomy=ask_each each mutate step then also raises an Approve/Deny permission interaction. Under approve_plan/auto_guarded both steps run automatically once the judge's input form is answered."
}

If any claim is unsupported, contradicted, or hallucinated, return false. Judge faithfulness only — not style.",

Developer notes & gotchas
  • Feature flags. CALIBER_FEATURE_COOKBOOKS=true opens the gallery and CALIBER_FEATURE_ARIA=true opens Plans; both are off by default.
  • Aria plans and executes: the planner leaves unknown fields empty, so each step pauses on an Aria needs information form (see ARIA-AUTONOMY.md).
  • The default planner keys off domain words — keep “judge” and “eval dataset” literal in the intent.
  • eval_dataset.create makes an empty test set; add rows from Observability afterward.
