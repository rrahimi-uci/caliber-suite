Cookbooks

Seventeen practical, build-along recipes that teach the CALIBER platform end-to-end — each backed by a versioned, installable system example with readiness checks and an explicit review-before-activation boundary.

17 cookbooks5 tracksUI-firstTraining-readyMermaid flows + UI mockups
How to read each cookbook.
  • Sign in at /caliber/login as admin / admin on a running stack.
  • Each cookbook has a flow diagram, a numbered UI walkthrough (the dark chip is the exact navigation path; “Fill in” lists every field; “Click” is the button to press), a UI mockup, an assets table, and quality gates.
  • Every green link opens the copy-paste asset file in that cookbook's assets/ folder — paste its contents into the matching field.
  • Preview areas are off by default. Each cookbook's notes name the feature flags it needs (CALIBER_FEATURE_COOKBOOKS for the gallery; CALIBER_FEATURE_ARIA for labs 12–15, CALIBER_FEATURE_INTEGRATIONS for lab 05 or CALIBER_FEATURE_RELEASE_CANDIDATES for lab 11). Set them on the server and restart. scripts/cookbook-env.sh up NAME --flags … starts a disposable stack with them.
The UI-first promise. With CALIBER_FEATURE_COOKBOOKS=true set on the server (off by default), open Cookbooks to install any of the 17 recipes as a paused workflow and editable draft. Review readiness before activation.
  • Test sets come from a file (Upload JSON/JSONL, labs 01 and 06) or from real runs (Observability → open a trace → Add to test set, lab 16).
  • The default model and evaluator are simulated. Evaluations refuses to score without a real model (400 evaluation requires a real LLM provider), and calibration evidence on the default stack is canned and marked Simulated evaluation — not evidence. Each lab says which of its steps are real and which are simulated.
  • Deterministic logic uses Data Transform for decisions, JSON Schema, mapping, confidence, and fixtures; Python Code remains a bounded extension.
  • Judges are for LLM-graded criteria; deterministic checks are scorers or assertions.
  • Aria (12–15) plans from one sentence in Plans (needs CALIBER_FEATURE_ARIA=true, off by default). The planner is rules, not a model; nothing runs until you approve the plan, each step asks for the fields it cannot know, and Aria creates the artifact once you approve.
