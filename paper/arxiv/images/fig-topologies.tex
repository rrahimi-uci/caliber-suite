\caption{The two deployment topologies. One ASGI application, two ways to run it;
the API and the SPA are identical, so the choice is a failure-domain and
operations decision rather than a feature one. Topology~A mounts \sys inside the
\mlflow{} server process as an \code{mlflow.app}, which is convenient for
development and couples the two failure domains. Topology~B runs \sys as its own
service reaching a vanilla \mlflow{} over HTTP. In neither mode is \sys a
transparent gateway in front of \mlflow{}: it is a sibling surface, not a proxy.
Two configuration facts are called out because both are load-bearing and both are
easy to get wrong. \cfg{CALIBER\_DATABASE\_URL} independently owns \sys's tables
and is not required to equal \mlflow{}'s backend store --- the bundled stack uses
separate logical databases precisely so the two Alembic histories never compete
for one version table. And ``artifact store'' names two different things:
\mlflow{}'s artifact root supports its full backend set including GCS, while
\sys's own storage service accepts \code{local} and \code{s3} only.}
\label{fig:topologies}
