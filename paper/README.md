# CALIBER technical paper

LaTeX source for *CALIBER: Per-Family Governance for Releasing AI-Agent
Resources*, in the authoritative single-column KOMA-Script `scrreprt` format.

## Build

```bash
cd paper
make stats     # regenerate the implementation counts from the source tree
make diagrams  # rebuild the Excalidraw architecture figures (needs node)
make           # build build/caliber-paper.pdf (4 pdflatex passes + bibtex)
make open      # build and open
make check     # lint the log for undefined refs and bad boxes
make repro     # regenerate implementation counts and force a checked rebuild
make clean
```

`latexmk` is not required — the toolchain is plain `pdflatex` + `bibtex`, which is
what a TeX Live *basic* scheme ships. `make` runs `make check` automatically and
**fails the build** on an undefined reference or citation, so those cannot ship
silently.

## Document format

The authoritative manuscript build uses KOMA-Script's report class:

```latex
\documentclass{scrreprt}
\usepackage{article-layout}
```

It includes a table of contents and starts every top-level section, Availability,
References, and appendix on a new page. `usenix-layout.sty` remains in `tex/` as
historical scaffolding; it is not an alternative authoritative PDF build.

### How one set of figures serves both measures

A figure-dense paper and a single-column measure pull against each other: a measure
wide enough for a 17 cm architecture diagram is too wide to read, and a readable
measure leaves those diagrams either overflowing or shrunk below a legible type
size. The resolution is that **nothing is ever scaled down**:

| Wrapper | Used by | What it does |
| --- | --- | --- |
| `cbwide` | the 6 conference-full-width figures, 3 wide tables | Centres the content at its authored size in a `\textwidth` box, letting it overhang the 3.3 cm margins by ~1.5 cm each side. Type size is untouched, so the 7 pt floor carries over exactly. |
| `cbscaled[f]` | the 5 conference-column-width figures | Scales content **up** to `f`×`\textwidth`. Scaling up moves type further above the floor, never below it. |

`cbscaled`'s factor is per-figure, not global, because these figures differ in
aspect ratio by more than 3× (`fig-asset` is 8.7 × 5.3 cm; `fig-execution` is
9.0 × 15.3 cm). One factor that suits the first overruns the page with the second.
The factors in use were chosen by **measuring** the pictures — compile a probe that
`\hbox`es each figure with the float and caption neutralised and read `\wd`/`\ht` —
not by guessing. If you change a figure's content, re-measure.

`make check` fails the build on `Float too large for page`, which is how an
over-tall float is caught: LaTeX prints it over the footer rather than erroring.

The Excalidraw figures sidestep this trade entirely: their scenes are authored in
**points at final printed size**, so `\includegraphics` places them with no scaling
and their 7 pt type really is 7 pt. That is worth knowing if you edit one — the
generator will refuse a scene whose type falls below the floor, but it cannot know
you meant to place it at a different width.

## Three conventions worth knowing before editing

**Every number comes from `macros.tex`.** Counts describing the implementation are
regenerated by `scripts/gen_stats.py`, which walks the CALIBER tree and emits
`generated/stats.tex`. Never type such a number into prose. Architectural constants
exist in three forms — numeral for figures and tables, lowercase word for prose,
capitalized for sentence starts (`\statScopes` / `\statScopesW` / `\statScopesC`) —
and the generator asserts all three agree.

**Terminology is enforced by macro.** The system distinguishes *governed asset* from
*asset family*, *candidate-advancement gate* from *advisory release verdict*, and
*containment* from *isolation*. Those distinctions carry technical weight, so they
are spelled by macro (`\gasset`, `\advgate`, `\relverdict`, …) rather than typed.

**Figure type has a floor.** `preamble.tex` defines the whole figure type scale in
three macros — `\figH` (headings), `\figB` (detail), `\figE` (edge labels), sized
relative to the body text. In the authoritative single-column layout that resolves
to 9 pt/8 pt. Nothing in a figure is set smaller. When a
diagram does not fit, *cut its content*, do not lower the floor: below 7 pt, figure
text is unreadable in print and in the two-page-per-sheet printouts many reviewers
use. Everything trimmed out of a diagram is restated in the prose.

## Figures and algorithms

Eleven figures, **all TikZ** by default. All four architecture figures also exist as
generated Excalidraw scenes (see `diagrams/README.md`); `\cbexcalidrawtrue` in
`tex/macros.tex` switches all four over in one edit. Both families share one palette
and node vocabulary assigned by *role* rather than by decoration, and
`diagrams/palette.py` asserts its colours against `tex/preamble.tex`, so they cannot
drift apart. Everything is vector; nothing depends on a raster asset.

### The figure style system

`tex/preamble.tex` holds one visual system every figure draws from, so a change to
it lifts all eleven at once:

| Style | What it is, and why |
| --- | --- |
| `cbbox` | The card: 2.4 pt corners, a 0.65 pt stroke, and a soft shadow. The shadow is what makes a six-band stack separate visually instead of relying on hue alone. |
| `softshadow` | Three offset copies at 4.5 % opacity, composed by hand. `shadows.blur` is absent from this pgf build, and TikZ's plain `drop shadow` is a hard offset copy that reads as clip-art at figure scale. |
| `flow` | `-{Stealth[round]}` with round caps and joins. At 7–8 pt label sizes a sharp arrow tip renders as a smudge; a rounded one stays a shape. |
| `boundary` | A dashed edge with a **double bar at midpoint** — the conventional mark for a boundary rather than a link. Used for the two dual-write crossings, so the edge states what it is without the caption. |
| `absent` / `advisory` | Semantic hatching. An empty cell is ambiguous in print (did the author forget?); a hatched one is a statement, and unlike a tint it survives greyscale. |

### The table system

The tables carry the paper's most contested claims, so they are built like figures:
a saturated header band with reversed type (which separates head from body without a
heavy rule), zebra banding so the eye tracks a row across six columns, banded group
subheads, rules marking the \sysbare{} column as the comparison's subject, and
**chips instead of dashes**. That last one is not decoration: `n/a` in a bordered
chip reads as a deliberate statement, whereas an em dash reads as a gap someone
forgot to fill — the opposite of what those cells mean.

Two LaTeX traps worth knowing before editing a table:

- **`\\` inside a `p`-column ends the row, not the line.** Use `\newline`. Getting
  this wrong shifts every column to the right of the cell, which looks like a
  content error rather than a markup one.
- **A TikZ chip inside a `\caption` breaks caption scanning**, because `caption`
  reads its argument more than once. The chip macros are `\DeclareRobustCommand`,
  and captions stay textual anyway so the list of tables holds no pictures.

### Why the Excalidraw figures are generated, not drawn

Drawing them in the browser would have cost four things the paper relies on.
Generating the scenes keeps all four, and the `.excalidraw` files it emits are still
real, editable Excalidraw documents:

1. **Numbers stay single-sourced.** `454 routes`, `71 tables` and the rest come from
   `generated/stats.tex` via `diagrams/stats.py`, not retyped into a JSON blob.
2. **One palette, asserted.** Not matched by eye.
3. **Reviewable diffs.** A `.excalidraw` file is JSON with random element IDs; a
   one-word change is an unreadable diff. The Python scene diffs by line.
4. **Reproducible builds.** Every rough stroke is seeded from its element index, so
   the SVG is byte-stable across machines and runs.

The scenes are authored at Excalidraw's **architect** sloppiness with solid fills
and the *Normal* font, because the paper targets a systems venue where the default
sketchy look reads as informal. `STYLE` in `diagrams/scene.py` holds those knobs;
raise `roughness` toward 1.5 for a blog or a deck.

Six guards fail the build rather than letting a defect reach the page, each for a
failure that is invisible in a visual check:

| Guard | The failure it catches |
| --- | --- |
| WinAnsi range | A glyph above U+00FF, which librsvg emits as a **Type 3** font. |
| Type 3 scan | Same failure, verified on the finished PDF in case a converter changes. |
| `NaN` scan | opentype.js's `toPathData` rounds by string concatenation and yields `NaN` for coordinates that stringify exponentially. Renderers abandon a subpath at a `NaN`, which shows up as a label whose last glyphs collapse into a blob. |
| 7 pt floor | Type below the paper's legibility floor. |
| Box overflow | Text wider or taller than the box that holds it, in either axis. |
| Palette drift | A colour that no longer matches `tex/preamble.tex`. |

Text is rendered as **outlines**, not SVG `<text>`: librsvg emits a companion Type 3
font for every text run even for pure ASCII, so no amount of rewording avoids it.
Outlines also make the output byte-identical regardless of installed fonts, and let
`opentype.js`'s real advance widths centre a label exactly. The typeface is Latin
Modern Sans — the paper's own `\sfdefault` — so figures and body text share a family.

Four algorithms carry the mechanisms the paper's claims reduce to:

| File | What it pins down |
| --- | --- |
| `alg-claim.tex` | Queue arbitration — concurrent exclusion via one conditional `UPDATE`; recovery remains per loop. |
| `alg-promote.tex` | Intent-first prompt-alias release, idempotent retry, and reconciliation. |
| `alg-gate.tex` | Both gates side by side — one returns control flow, one returns a record. |
| `alg-resolve.tex` | The client read path — the entire cost surface E1 measures. |

### Requested TikZ libraries: what is loaded, and what is not

Loaded and used: `arrows.meta`, `positioning`, `calc`, `fit`, `backgrounds`,
`decorations.pathreplacing`, `decorations.markings`, `patterns`, `patterns.meta`.

Deliberately **not** loaded, with reasons recorded in `tex/preamble.tex` beside the
`\usetikzlibrary` call: `shadows` and `shadows.blur` (the latter is not in this pgf
build; both are superseded by `softshadow`), `shapes.geometric` (the cylinder was
tried for the three datastores and reverted — it sizes its body from the node text
and then adds elliptical caps, so a box holding seven lines becomes enormous and the
text escapes it), `shapes.misc`, `matrix`, `chains` (the grid and pipeline figures
are already exactly aligned by computed coordinates), `graphs`, `petri` (would suit a
state-machine view of queue arbitration — a new figure, not an improvement to an
existing one), `mindmap`, and `graphdrawing` (needs LuaLaTeX; the paper does build
under `lualatex`, but automatic layout is worse than computed placement for block
diagrams whose column alignment carries meaning, and switching engines would mean
revalidating the Type 1 font work).

Three conventions keep the diagrams maintainable:

- **Brace-wrap coordinate arithmetic** — `at ({\X+\i*(\w+\G)}, -1.2)`. TikZ's
  coordinate parser mis-splits nested parentheses without the braces.
- **Anchor-relative placement for text-heavy rows** — `at ([yshift=-4mm]prev.south
  west)` rather than a fixed `y`. Boxes holding several lines of small text grow
  when the wording or the type scale changes, and absolute placement collides
  silently.
- **Reserved routing lanes** — long edges run in a named gutter, an outer lane, or a
  channel below a band. No edge crosses a box.

## Font notes

Three font decisions are deliberate and load-bearing on a basic install:

- **`mathptmx` is not loaded.** Its virtual math fonts reference `rsfs10`, which
  ships with the `rsfs` package and not with a basic scheme; the failure surfaces
  only at shipout, as an unloadable TFM.
- **`\ttdefault` and `\sfdefault` are Latin Modern**, not `times.sty`'s Courier and
  Helvetica, whose T1 metrics are absent here.
- **T1 and TS1 substitutions are pinned to Times**, and `\dt` (the figure separator)
  is drawn with a rule rather than set from TS1. Both prevent Metafont bitmaps from
  embedding as **Type 3** fonts — a routine camera-ready rejection. Verify with
  `pdffonts build/caliber-paper.pdf`: every entry should read `Type 1`.

## Two known issues

**Length.** The authoritative `scrreprt` build is 71 pages after adding the
four-page contents section and new-page section boundaries. It is a technical
report, not a conference-length manuscript. Any conference submission needs a
separate venue-specific edition and substantial cutting. The content is structured
so cutting is mechanical. In rough order of least to most damage:

1. Fold §9 (Implementation) into §5 and move `tab-impl` to an appendix (~1 page).
2. Move §8 (Design Decisions) prose to an appendix, keeping only `tab-decisions`
   in the body (~2 pages).
3. Merge §2 (Motivation) into §1, keeping the nine-step enumeration and cutting
   the "obvious answers" subsection (~1.5 pages).
4. Merge §6 (Core Components) into §5, keeping the gate-semantics and audit
   subsections, which other sections depend on (~2.5 pages).
5. Move `alg-resolve` and `alg-gate` to an appendix, keeping `alg-claim` and
   `alg-promote` in the body (~1 page).
6. Drop `fig-asset` and `fig-execution`, folding their content into `fig-layers`
   and prose respectively (~1.5 pages).
7. Compress §3 (Background) to two paragraphs per group (~1.5 pages).

Do **not** cut `tab-families`, `fig-chain`, `alg-promote`, or §5.1 — the central
claim depends on all four.

**Unrun evaluation.** `tab-results` is deliberately empty; every quantitative cell
renders as `\pending` (a coloured *TBM* marker) rather than as an estimate. The
protocol is specified in `appendix/c-protocol.tex` in enough detail to execute. When
results arrive, replace the `\pending` cells — no surrounding prose needs to change,
and §10.1 and §12.1 should then be rewritten.
