# D3 / #1051 — governed public-caller dispositions

## Scope

This slice closes the caller-level integration audit around the existing governed worker context.
It does not add a new connector or recreate nested HTTP park/resume. The public caller matrix records
which paths own an admitted run, which are preview-only, and which must refuse because they have no
run-owned authority.

## Contract proved

- An admitted queued worker run owns the execution-owner lease, pinned grant/manifest, approval provider
  and configured receipt verifier before a protected effect or governed agent step can run.
- A nested workflow inherits the parent run's exact context and stable occurrence namespace; it does not
  invent independent authority. Listed HTTP effects can park, resume and reconcile; unsupported backends
  remain `no_authoritative_verifier`.
- Synchronous real runs remain rejected with `sync_run_not_admitted` when admission is enabled. A request
  process does not become an execution owner by calling the synchronous route.
- Evaluation, refinement, calibration, deploy-gate and Aria preview paths do not receive production-run
  authority. Protected work is preview-stubbed or refused according to the existing profile contract.
- Aria `run_workflow` is an enqueue boundary. The worker, not the assistant tool, owns the governed execution.
- Standalone exports and caller-built plans have no implicit authority. Reference-profile protected work
  refuses before an ungoverned call; development retains its explicitly documented legacy behavior.
- EP-017 and EP-081 now have explicit caller dispositions and test evidence. EP-090 remains the separate
  no-production-caller inventory ratchet owned by #1088. EP-009/010/013/051/059/070–077 remain outside
  this slice under #1086/#1087.
