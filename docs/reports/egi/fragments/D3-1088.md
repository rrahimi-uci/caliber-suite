# D3 / #1088 — reference workflow-version response boundary

## Scope

This fragment records the evidence for the remaining #1088 acceptance work. The source-redaction
implementation itself is already present on `main` through PR #1133; this change qualifies that behavior
on the public route boundary, preserves the storage contract, closes the foreign-project identifier leak,
and reconciles the effect-path ownership documentation.

## Contract proved

- In `CALIBER_PROFILE=reference`, `POST /workflow-versions/{id}/compile`, `GET /workflow-versions/{id}`,
  and `POST /workflow-versions/{id}/publish` omit the `generated_python` field and its source bytes.
- The compiled bundle remains stored internally so the platform can use its immutable artifact; the response
  filter is not a destructive storage change.
- A caller in another project receives a generic 404 for a hidden version and cannot learn the supplied
  version identifier from the error body or obtain generated source.
- The development profile continues to expose generated source for the existing local-development contract.
- EP-017 and EP-081 remain explicitly `unrouted` in the effect matrix and are owned by #1051 for caller-level
  authority/refusal work. EP-090 retains its AST no-caller ratchet and remains owned by #1088.
