Governed Evidence Review

Take one synthetic missing-document request through approval, one verified effect, complete evidence and non-mutating replay.

GovernBeta30–60 min
What you build. An evidence-review path that stops for a person. An editor admits a run for the pinned Harborlight case; the scripted model proposes request_missing_document; a distinct approver approves the exact proposal; an operator resumes; the trusted document-request connector commits once and verifies the receipt by read-back. The final export joins the run, proposal, approval, decision, effect and downstream request, and offline replay reports matched without another mutation. The case is synthetic and the scenario never makes a credit decision.
Surfaces: Workflows Observability Audit Log Cookbooks
What you learn
  • Read the Beta scope and reference-profile contract before installing a governed effect recipe
  • Inspect a run parked at waiting_approval and the exact proposal arguments: case MORT-2026-000184, pay_statement, expected version 1
  • See the initiating editor refused with 403 project_role_required, then approve as a distinct project user with the platform approver scope
  • Verify the downstream contract: first commit 201, same-key replay 200, stale If-Match 412, and exactly one mutation
  • Trace causal links across the run, approval, policy decision, receipt and downstream request; export the evidence and replay it without an outbound write
  • Check project isolation and fail-closed unknown/unbound verifier paths rather than treating a missing authority as success

Developer notes & gotchas
  • Profile. Start from docs/start/beta-scope.md and the reference profile. The disposable scenario binds the existing D1 downstream and uses the B15.1 provenance-pinned fixture; it does not create a parallel service.
  • Two people plus an operator. The initiating editor cannot approve. The approver must be distinct and hold the platform approval scope; the worker lease and resume path remain operator-controlled.
  • Refusals are evidence. project_role_required, scoped 404, no_authoritative_verifier, connector_unbound and stale 412 are expected outcomes, not flaky setup failures.
  • Deterministic CI. The model, clock and downstream are scripted/local. The fixture is synthetic and not for credit decisions; ordinary tests never call a live provider or customer system.
  • Run it. scripts/cookbook-run-all.sh --labs 22 runs the registered API path when the dependent V01 and installed SDK artifacts are present; the browser journey is supplied by B15.3b.
