Cookbook 12 · Aria — Autonomous

Aria: Evaluation Harness from Intent

One sentence → a rules-based Aria plan creates a judge and a Test Set; you fill their fields, approve each change, load 30 cases and see what Aria refuses.

Aria — AutonomousAria15–30 min
What you build. You give Aria one sentence, Create a judge for answer faithfulness and an eval dataset to run it on., and it draws a two-step plan, judge.create then eval_dataset.create. Nothing runs until you approve; each step then stops on an Aria needs information form and, with Stop before each change, an Approve / Deny prompt. At the end a real active judge (AnswerFaithfulness, bool) and a real, empty Test Set exist; you add 30 support cases from faithfulness-cases.jsonl and exercise the refusals.
Surfaces: Plans Judges Test Sets Evaluations
What you learn
  • State an intent on Integrations > Plans (Goal, Autonomy: Stop before each change, Decompose goal) and read the draft before you approve it
  • Understand that the planner is deterministic rules, not a model: it adds a step for every domain word (judge, eval dataset, test set) and was checked against 28 goals (28/28)
  • Answer a step's Aria needs information form (name, instructions, feedback value type) and its approval prompt; each step asks for its own name, nothing is wired between them
  • Verify the artifacts in Agent resources > Judges and Prompt lifecycle > Test Sets, then add rows with + Add example (30 cases, one version per row)
  • See the refusals: a sentence with no steps cannot be approved (409), a bad form answer keeps the question open, a judge with no evaluation variable fails its step and the plan, and an account without the operator scope creates nothing

assets/intent.md 
# The intent you give Aria

## Canonical (works with the default planner)

> Create a judge for answer faithfulness and an eval dataset to run it on.

Why this wording: the default planner proposes a step for each capability whose
**domain word** appears in the goal. "judge" gives `judge.create`; "eval dataset"
(or "test set") gives `eval_dataset.create`. Keep both words in the sentence.

Autonomy: **Stop before each change** (`ask_each`: an **Approve** / **Deny** prompt
before every step that changes something, after the input form).

## What the planner does with other sentences

`dataset/goals.jsonl` holds 28 goals and the plan the server draws for each one;
the script checks all 28 against the real server. In short:

- Wording with `judge` and `eval dataset` / `test set` / `test-set` / `testset` /
  `eval_dataset` (any case) gives the right steps, in any phrasing.
- "faithfulness scoring" gives no judge step, and "evaluation dataset" gives
  nothing at all: the planner looks for the exact domain words, there is no
  language model behind it.
- It does not read negation (`Do not create a judge...` still plans a judge), it
  matches `judge` inside `judgement`, and a question that contains the word
  (`What is a judge in CALIBER?`) also plans a step. That is why you read the plan
  before you approve it: nothing runs until you do.
- A sentence with no domain word makes a plan with no steps; it cannot be approved
  (HTTP 409).

Developer notes & gotchas
  • Flags. CALIBER_FEATURE_ARIA=true opens /aria/* and Plans (404 feature_disabled without it); CALIBER_FEATURE_COOKBOOKS=true is only needed for the gallery card. Start the stack with scripts/cookbook-env.sh up lab12 --flags cookbooks,aria.
  • Operator accounts. Export CALIBER_OPERATOR_USERS=admin,olga before starting the stack: judge.create and eval_dataset.create need caliber.operator, and vera (created by the script) must not be an operator.
  • Simulated vs real. The planner is rules (no model, same on a real deployment); judge.create, eval_dataset.create and the 30 rows are real. With the default fake LLM/eval providers Evaluations is refused (400 evaluation requires a real LLM provider), so the lab verifies the refusal, not a score; Ask Aria is not used.
  • Planner limits. It does not read negation, synonyms beyond testset / test set / test-set / eval dataset / eval_dataset, or questions, and matches judge inside judgement. "Faithfulness scoring" and "evaluation dataset" do not match, so read the plan before approving.
  • Empty Test Set. eval_dataset.create makes an empty set; adding the 30 rows is not an Aria capability (API POST /eval-datasets/{id}/examples, UI + Add example; the UI recipe adds three by hand).
  • Failed plans stay failed. A failed plan cannot be executed again (409): state the goal again with a new name or fixed instructions. Plans cannot be deleted; the script cancels its drafts and --cleanup archives the cookbook-12-* judges and test sets.
  • Run it. PYTHONPATH=sdk/caliber-sdk caliber/.venv/bin/python -m examples.cookbooks.cookbook_12_aria_evaluation_harness (example: sdk/caliber-sdk/examples/cookbooks/cookbook_12_aria_evaluation_harness.py) with an admin CALIBER_TOKEN.
