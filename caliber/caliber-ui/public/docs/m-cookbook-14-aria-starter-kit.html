Aria: Governance Starter Kit from Intent

The flagship: one sentence → a plan for a judge + test set + review queue together.

Aria — AutonomousAria20–30 min
What you build. Aria decomposes a single intent into a whole evaluation+governance scaffold (judge.create + eval_dataset.create + review_queue.create); you fill the judge's and queue's fields in the plan's input forms and approve each step.
Surfaces: Plans Judges Test Sets Review Queues Evaluations
What you learn
  • Compose three capabilities in one plan from one intent
  • Recognize the three planner needles in the goal
  • Fill the judge and queue input forms and approve each step
  • Assemble a reusable governance starter kit
  • Hand the kit to cookbook 10 for scoring

Implementation flow

flowchart TD
  I[/"Intent: judge + eval dataset + review queue"/] --> PL[Aria Plans]
  PL --> J[judge.create] -.input form.-> JU[Judges]
  PL --> Q[review_queue.create] -.questions form.-> RQ[Review Queues]
  PL --> D[eval_dataset.create] -.name linked.-> TS[Test Sets]
  PL --> A[review_queue.add_items] -.Skip step.-> SK[skip]

assets/intent.md 
# The intent you give Aria

## Canonical (works with the default HeuristicPlanner)

> Stand up our governance starter kit: a judge for answer faithfulness, an eval dataset to score against, and a review queue for human checks.

Why this wording: the default planner proposes a step for each capability whose
**domain word** appears in the goal. "judge" → `judge.create`; "eval dataset" →
`eval_dataset.create`; "review queue" → `review_queue.create`. Keep all three
literal needles in the sentence.

Note: "review queue" matches BOTH `review_queue.create` and
`review_queue.add_items` (they share the domain), so the planner proposes both.
There are no traces yet, so click **Skip step** on the `add_items` form.

Autonomy: **Stop before each change** (`ask_each`: an **Approve** / **Deny** prompt before every mutate step, after the input forms).

## Natural-language variant (not understood by the default planner)

> Get our new support answers governed end to end: score them for faithfulness, keep a held-out test set, and let a human spot-check the tricky ones.

This reads better, but the default heuristic planner only recognises "test set"
(→ eval_dataset); "score for faithfulness" has no judge needle and "human
spot-check" no review-queue needle, so it plans only the test-set step. Use the
canonical wording.

  "autonomy": "ask_each",
  "expected_steps": [
    {
      "capability_key": "judge.create",
      "tier": "mutate",
      "interaction": "input form (Aria needs information): enter the judge fields from judges/answer-faithfulness.judge.json, then Approve"
    },
    {
      "capability_key": "review_queue.create",
      "tier": "mutate",
      "interaction": "input form: enter questions (and optional description) from review-queues/governance-review.queue.json, then Approve; name is linked from judge.create"
    },
    {
      "capability_key": "eval_dataset.create",
      "tier": "mutate",
      "interaction": "no input form: name is linked from review_queue.create, so just Approve (datasets/release-candidates.dataset.json is a reference spec)"
    },
    {
      "capability_key": "review_queue.add_items",
      "tier": "mutate",
      "interaction": "SKIP this step (Skip step / answer {approved:false}) — no traces to enqueue yet. It is proposed only because it shares the 'review queue' domain. Enter trace_ids instead if you already have traces; queue_id is linked from review_queue.create."
    }
  ],
  "notes": "Step order follows registry order; the planner links required fields by output name: review_queue.create.name <- judge.create, eval_dataset.create.name <- review_queue.create, review_queue.add_items.queue_id <- review_queue.create (depends_on set accordingly). The 'review queue' needle matches both review_queue.create and review_queue.add_items, so both appear. judge.create, review_queue.create and add_items raise input interactions for their unfilled fields; under autonomy=ask_each each step then also raises an Approve/Deny permission interaction (skip add_items). Under approve_plan/auto_guarded the steps run automatically after their input forms — so for this scenario prefer ask_each so you can skip add_items."
}
