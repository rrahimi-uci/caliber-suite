The problem
Agentic workflows are easy to build and hard to trust.
Prompts, tools, and multi-step agents ship faster than anyone can govern them. They drift, they're tuned by feel, and the lineage — what changed, how it scored, who approved it — lives in chat threads and notebooks instead of one system of record.
?
No eval gate
Changes ship without a measured score against a held-out set
?
No lineage
What changed, why, how it scored, who approved — unrecorded
?
No rollback
When a workflow regresses, there's no clean way back
Every shipped artifact should answer: how did it score, who approved it, and how do I revert it?
Introducing
One same-origin control plane for agentic workflows.
CALIBER is an MLflow application plugin: it mounts its SPA and API on the same server as MLflow, so designing, evaluating, calibrating, publishing, and observing every agent resource happens against one identity, one store, and one trace backend.

The platform
Build composes. The Library supplies.
Every agent resource is a first-class, versioned asset with its own "pytest-for-an-asset" workspace — a status header, stage tabs, and durable test runs — so you develop and verify each one in isolation before a workflow ever uses it.

Prompts

Versioned against MLflow's Prompt Registry, with aliases and a per-prompt test workspace.

Tools

Definitions runnable in a subprocess sandbox; test a draft against inputs before publishing.

Skills

Named capabilities with selection logic; preview which skills resolve for an input.

MCP Servers

Registered Model Context Protocol servers — including a first-party database server — exposed as tools.

Knowledge Bases

Hybrid retrieval (BM25 + dense RRF, tri-hybrid with graph) plus retrieval calibration.

Workflows

Agentic graphs composed in Studio, preview-run, published, and traced end to end.

Measure
Evaluate, then calibrate — with receipts
Evaluation runs a test set through scorers and compares runs. Calibration goes further: it searches for a better version of an asset and gates promotion on a measured score against the held-out set — a closed learning loop that refines each asset against real evidence.

Observe
Every run is a trace you can open
Observability is built on MLflow tracing: each workflow run records per-tool-call spans, and the Evaluations surface turns those traces into scorecards, per-example results, and run-to-run comparisons.

Aria
An embedded copilot that runs, observes, and fixes
On OpenAI and Claude, Aria runs a real tool-calling loop inside one turn: it reads live CALIBER state, executes capabilities, observes the result — including a workflow run's trace and scored evaluations — and iterates, bounded to eight tool steps.

Modes

  • chat talks · plan outlines
  • build materializes drafts
  • Attachments, queue, and steering

Permissioned tools

  • Read in every mode
  • Sandboxed/reversible in auto_safe
  • Runs & publish only in auto_all

Governed

  • Drafts ride the same gates
  • Tool calls recorded per turn
  • Autonomy bounded & auditable

The vision
Agentic workflows you can measure, refine, govern, and trust.
CALIBER : Contextual Adaptive Lifecycle for Intelligent Build, Evaluation, and Refinement is open source and MLflow-native, learning from real evidence to refine every asset across its lifecycle.

Native

Mounts at /caliber as an mlflow.app plugin. Same-origin with MLflow's AJAX API and trace backend.

Agentic

Aria runs a permissioned tool loop on OpenAI and Claude — read state, execute, observe, iterate — inside the product.

Measured & refined

A learning loop: evaluation scorecards and per-asset calibration refine each asset, gating promotion on real scores against held-out test sets.

Governed

Validate → test → approve → publish for every artifact, with RBAC, audit, and explicit operator apply.

Observable

MLflow tracing with per-tool-call spans on every run; readiness honestly reports real vs simulated providers.

Open

Apache 2.0 · Python 3.11+ · SQLAlchemy 2.0 · React SPA · object-storage-backed · No vendor lock-in.
