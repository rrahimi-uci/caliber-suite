Cookbook 08 · Build

Incident Response Copilot

Turn an incident record into a severity and the lowest-risk action, gate a rollback behind a second person, and release to prod only through a deploy gate.

BuildAdvanced40–65 min
What you build. An incident-commander workflow (14 nodes) that turns an incident record (alert, deployments, health numbers, a noisy log excerpt, paging and customer-report counts) into a severity and an action using declarative decision tables (Data Transform, Join, Template, Router), and pauses a rollback at a human approval. Because nothing in the decision needs isolating, Preview can run it, and the prod alias carries a deploy gate that replays the 41-incident test set incident-cases before it moves. The only agent node, draft_update, runs on the simulated provider and its text is never asserted.
Surfaces: Administration Workflows Test Sets Cookbooks Audit Log
What you learn
  • Express a severity and action policy as two decision tables (first match wins) and check all 41 incidents: 8 sev1, 10 sev2, 12 sev3, 11 sev4, including noisy logs, conflicting evidence, missing metrics and the boundary cases IN40 and IN41
  • Import a workflow that names a test set: it is refused with unresolved_import_dependency until the test set incident-cases exists in the workspace
  • Promote to prod through a deploy gate that replays the test set (pass rate 1.0, executor reported as fake), wait for a second person's approval, and see a bad version refused with 400 deploy gate failed (pass rate 0.9512)
  • Gate only the 5 rollback incidents (IN01, IN11, IN12, IN15, IN23) at the review node: self-approval is 403, an approval releases ROLLBACK_APPROVED, a rejection releases nothing
  • Run the failure drills: Error Boundary fallback, a missing tool refused at import, a blocked API Request host, and Wait For Event pause and resume

Implementation flow

flowchart TD
  S[start: incident JSON] --> FO[fan_out: parallel]
  FO --> IN[ingest]
  FO --> SV[severity_table]
  FO --> AC[action_table]
  FO --> DU[draft_update: agent, simulated]
  IN --> J[join]
  SV --> J
  AC --> J
  DU --> J
  J --> SU[summarize: Verdict]
  SU --> RT{triage_router}
  RT -->|rollback| HA{{review: human_approval}}
  HA -->|approve| RR[rollback_request]
  RT -->|escalate_human| HN[handoff_note]
  RT -->|other actions| RC[recommendation]
  RR --> F[final]
  HN --> F
  RC --> F

Step-by-step UI only

Each step shows the exact navigation path, the fields to fill, the button to click, and a snapshot of the CALIBER screen you'll be on.

  1. Admin › Administration
    Create lena and sam under Accounts (password cookbook08-lab-passphrase), create a workspace with the top bar +, and add both as Reviewer under Project access. The server must list lena in CALIBER_APPROVER_USERS.
    Click Add member
    You'll see: Created lena. then Added lena to <workspace>.
    Screen snapshot
  2. Agent resources › Workflows › Import incident-commander.workflow.json ↓
    The manifest's deploy gate names a test set. Import it before that test set exists: Import, type a name, Choose file incident-commander.workflow.json (with artifacts.eval_datasets.incident-cases.dataset_name set to the name you will use), Validate dependencies.
    Click Validate dependencies
    You'll see: Preflight needs attention and is not visible in this workspace: the import is refused until the test set exists.
    Screen snapshot
  3. Prompt lifecycle › Test Sets incident-cases.jsonl ↓
    Press + New Test Set, type the name from the manifest, owner @lab08, Create, open it and press + Add example three times, pasting the input and expected of IN01, IN03 and IN06 and their tags. (The API path loads all 41 rows; the form adds one at a time.)
    Click Save
    You'll see: The test set lists three example rows.
    Screen snapshot
  4. Agent resources › Workflows › Import
    Import again with the same file and name, Validate dependencies, then Import as new.
    Click Import as new
    You'll see: Preflight passed; the editor opens with severity_table, action_table, join, triage_router and review in the outline.
    Screen snapshot
  5. Workflows › editor
    Press Validate, then Preview, paste the IN01 incident and press Run Preview, and open the summarize step. Unlike a Python Code workflow, this one previews.
    Click Run Preview
    You'll see: The toolbar says Valid.; the preview is completed and the summarize step shows sev1 rollback.
    Screen snapshot
  6. Workflows › editor
    Press Publish, Run Validation, Next, Next, Publish.
    Click Publish
    You'll see: The toolbar says Published. The alpha UI has no Deployments or Promotions tab: the staging and gated prod aliases, the deploy gate and rollback are API only.
    Screen snapshot
  7. Workflows › editor › Run Monitor
    Open Run Monitor, paste an incident ({"incident": {...}}) and press Run. Run IN06 (healthy staging), then IN01 (gateway regression after a deploy). Then press Approve on the IN01 run as the same account.
    Click Run
    You'll see: IN06 completes with RECOMMENDATION and sev4 monitor. IN01 stops at waiting_approval; Approve as the starter shows a second person must decide.
    Screen snapshot
  8. Workflows › (workflow) › Runs, as lena
    Sign in as lena, choose the workspace, open Workflows, the workflow and its Runs tab, select the run that shows Awaiting approval, press Approve, then Resume.
    Click Resume
    You'll see: The run's output contains ROLLBACK_APPROVED and the sev1 rollback verdict. (Evaluations can also score a Workflow version as the subject, at most 20 examples per run; with the simulated provider it answers 400 evaluation requires a real LLM provider.)
    Screen snapshot

Developer notes & gotchas
  • Prerequisite flag. CALIBER_FEATURE_COOKBOOKS=true (scripts/cookbook-env.sh up lab08 --flags cookbooks). The optional MCP evidence nodes of the original recipe would also need CALIBER_FEATURE_INTEGRATIONS=true; they are not part of this lab.
  • Release policy settings. Export CALIBER_OPERATOR_USERS=admin,lena,sam, CALIBER_APPROVER_USERS=admin,lena, CALIBER_RELEASE_REQUIRE_HUMAN_APPROVAL_FOR_ENVIRONMENT_CLASSES=production and set CALIBER_RELEASE_REQUIRE_GRADED_EXECUTOR_FOR_ENVIRONMENT_CLASSES to empty. Left at its default production, the prod promotion is refused until a real model is configured.
  • What is simulated. The decision is deterministic tables (no model). The deploy gate replays with the fake executor and says so (provider: fake, deterministic: true): it proves the graph and the data, not a model. Evidence is supplied inside each incident record. Evaluations on a workflow version is refused (400) without a real model.
  • Workflow calibration finds no candidate. On this rule-table workflow it runs, reports a baseline and finishes rejected (no candidate met calibration gates), so the Simulated evaluation marker was not observed here.
  • API-only parts. Aliases, the prod gate, promotions and rollback have no UI in this alpha build (single-environment mode); the UI spec covers import, Test Sets, Preview, publish, run and approve. Preview refuses a Python Code or API Request node.
  • Not covered. Live evidence (deployment and service-health APIs, a status-page snapshot, an incident issue) needs egress, MCP servers and credentials; the GitHub, Playwright and PostgreSQL MCP steps were removed, not run. assets/prompts, skills and judges are reference only.
