Aria: Triage & Recalibrate Loop

One sentence → review the weak runs, then kick off an async workflow calibration.

Aria — AutonomousAria20–35 min
What you build. On an existing workflow with weak runs, Aria plans review_queue.create + add_items + the async workflow.calibrate; you enter the queue schema, the flagged trace ids and the workflow + agent ids in the plan's forms, then watch the plan park and resume on its own.
Surfaces: Plans Review Queues Workflows Observability
What you learn
  • Plan a remediation loop from one intent
  • Operate on existing ids (traces, workflow, agent)
  • Read flagged trace ids from Observability
  • Trigger a workflow calibration from the plan
  • Understand async parking and automatic resume in Aria plans

Implementation flow

flowchart LR
  I[/"Intent: review the flagged traces + calibrate the workflow"/] --> PL[Aria Plans]

  10. Integrations and preview › Plans › PLAN-… (waiting on a job) creates · Plan resumed and completed after the async job
    Let the async job run. This is the genuinely asynchronous part of the loop and there is nothing to click: the plan worker polls the job about every 10 seconds and resumes the plan by itself. Refresh the plan page (the Plans UI has no Poll button) until the step leaves WAITING JOB. The job counts as done when it reaches candidate_ready (or applied); rejected, failed or error fails the step and the plan. The plan does not apply the candidate. (Over the API, POST /aria/plans/{id}/poll advances it on demand.) With the default fake evaluator the job's scores are canned.
    You'll see: The workflow.calibrate row flips to DONE and the plan reaches COMPLETED with all three steps done.

The Aria plan (under Plans, status COMPLETED, all three steps done) is the orchestration record for the whole triage → remediation loop.
    You'll see: A populated weak-runs-triage queue, a finished calibration run on the workflow, and a completed Aria plan — the governance → remediation loop end to end.
    Screen snapshot

Then compare the recalibrated workflow against its baseline runs and feed the hard cases into its eval dataset (see SCN-01 / SCN-10) to keep tightening the loop.
    You'll see: Submitted reviews write assessments + expectations back onto the traces, giving you ground-truth labels to compare the recalibrated workflow against its baseline.

# The intent you give Aria

## Canonical (works with the default HeuristicPlanner)

> Our workflow's recent runs look weak — set up a review queue for the flagged traces and kick off a workflow calibration.

Why this wording: the default planner proposes a step for each capability whose
**domain word** appears in the goal. The phrase **"review queue"** maps to
**both** `review_queue.create` **and** `review_queue.add_items`; the word
**"workflow"** (calibration) maps to `workflow.calibrate`. Keep both literal
needles in the sentence.

Autonomy: **Stop before each change** (`ask_each`: an **Approve** / **Deny** prompt before every mutate step, after the input form).

## Natural-language variant (not understood by the default planner)

> Our latest runs aren't great — get a human to look at the bad ones and then tune the pipeline.

This reads better, but the default heuristic planner has no mapping from "get a
human to look at the bad ones" to the review-queue steps or "tune the pipeline"
to `workflow.calibrate` (the sentence contains neither "review queue" nor
"workflow"), so it plans nothing. Use the canonical wording.

## Remember: this loop remediates EXISTING things

`review_queue.add_items` needs **real existing** `trace_ids` and
`workflow.calibrate` needs an **existing** `workflow_id` + `agent_id`. Aria does
not create the subject workflow or its traces — build that in **SCN-07** first,
then enter the ids in the input forms when Aria pauses (see [`enqueue.json`](enqueue.json) and
[`calibrate.json`](calibrate.json)).

Developer notes & gotchas
  • This is a remediation loop — it operates on EXISTING ids (traces, workflow, agent). Build the subject workflow in cookbook 07 first.
  • workflow.calibrate is Aria's async capability: the plan parks (waiting_job) and the plan worker resumes it (POST …/poll also works over the API).
  • As elsewhere in the Aria track, the planner leaves the inputs empty and the plan's input forms collect them. The default evaluator and LLM are fake, so a default install's calibration scores are canned.
