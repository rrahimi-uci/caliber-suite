Aria: Triage & Recalibrate Loop

One sentence about weak runs → a three-step plan creates a review queue, enqueues 12 flagged traces and parks on a real calibration job that settles on its own.

Aria — AutonomousAria20–35 min
What you build. On a workflow, agent and flagged traces that already exist (created first by assets/setup_subject.py and assets/seed_traces.py), Aria draws review_queue.create, review_queue.add_items and workflow.calibrate from one sentence. You answer six questions (a form and an approval per step); the last approval queues a real calibration job and the plan parks (running, step waiting job). The plan worker resumes it with no click and the plan ends where the job ended, while a reviewer triages the 12 flagged traces in Review Queues.
Surfaces: Plans Review Queues Workflows Observability
What you learn
  • Plan a remediation loop from one intent: it operates on existing ids (trace ids, workflow id, registered agent id), Aria creates neither the traces nor the workflow
  • Wire and answer the forms: the enqueue step's only wired input is the queue id; enter the 12 trace ids from Observability or seed_traces.py, and the workflow and agent ids from setup_subject.py
  • Watch an async step park and resume: approving workflow.calibrate leaves the plan running with the step waiting job; the page re-reads every five seconds and a parked plan cannot be cancelled (409)
  • Triage flagged runs in Operate > Review Queues (resolution_correct, failure_mode, severity, expected_answer); answers land on the trace as assessments, the expected answer as its expectation
  • See the refusals: an unknown workflow, unregistered agent or workflow with no deploy-gate test set fails the step at once without queueing a job, and a denied calibration queues nothing

assets/intent.md 
# The intent you give Aria

## Canonical (works with the default planner)

> Our workflow's recent runs look weak - set up a review queue for the flagged traces and kick off a workflow calibration.

Why this wording: the default planner proposes a step for each capability whose
**domain word** appears in the goal. "review queue" gives `review_queue.create` **and**
`review_queue.add_items` (same domain); "workflow" gives `workflow.calibrate`. Keep both in
the sentence.

Autonomy: **Stop before each change** (`ask_each`: an **Approve** / **Deny** prompt before
every step that changes something, after the input form).

## This loop remediates things that already exist

`review_queue.add_items` needs trace ids that exist, and `workflow.calibrate` needs a workflow
and an agent that exist. Aria creates neither: it does not discover traces, and it cannot
build a workflow (`Create a new workflow for returns.` plans a *calibration*, not a workflow).
`setup_subject.py` creates the lab's subject (two tools, a published workflow with its test
set as the deploy gate, an agent) and `seed_traces.py` writes the flagged traces; in a real
deployment they are yours.

## What the planner does with other sentences

`dataset/goals.jsonl` holds 28 goals and the plan the server draws for each one; the script
checks all 28 against the real server. In short:

- Any sentence with `review queue` plans both the queue and its enqueue step; any with
  `workflow` plans a calibration, whatever the sentence is about (`We are in the middle of a
  workflow outage.` plans one). Both can appear in one plan, always in the order queue, enqueue,
  calibrate.
- "pipeline", "tune", "human review", "get a human to look" and "re-run the evaluation" are
  not domain words: `Tune the pipeline and get a human to look at the bad runs.` plans nothing.
  There is no language model behind the planner.
- It does not read negation (`Do not calibrate the workflow, only set up the review queue.`
  still plans the calibration), questions, "rebuild" or "roll back": there is no capability
  for those, and the word `workflow` still plans a calibration.
- A sentence with no domain word makes a plan with no steps; it cannot be approved
  (HTTP 409).
assets/setup_subject.py 
#!/usr/bin/env python3
"""Create the things lab 15 remediates: the tools, a published workflow, its test set and an agent.

Aria's plan in this lab does not create any of them (``workflow.calibrate`` takes an *existing*
workflow and agent), so a fresh stack needs them first. In a real deployment they are your own.
This registers the two tools (``lookup_policy``, ``get_order``; one that is already registered is
kept), loads the 30 cases of ``dataset/support-runs.jsonl`` into a test set, imports and publishes
``workflows/support-policy-agent.workflow.json`` with that test set as its deploy gate, and
registers an agent. Every name carries ``--suffix`` so a second run does not collide with the first.

    export CALIBER_BASE_URL=http://127.0.0.1:5001   # the server root
    export CALIBER_TOKEN=calpat_...      # an admin token (or CALIBER_USER / CALIBER_PASSWORD)
    PYTHONPATH=sdk/caliber-sdk caliber/.venv/bin/python \
        docs-site/cookbooks/15-aria-triage-recalibrate-loop/assets/setup_subject.py --suffix demo

Prints ``{"workflow_id", "agent_id", "dataset_id", "workflow_name", "gate_name", "tools"}`` as JSON.
"""

from __future__ import annotations

import argparse
import json
import os
import sys
import time
from pathlib import Path
from typing import Any

ASSETS = Path(__file__).resolve().parent
NAME_PREFIX = "cookbook-15-"


def register_tools(caliber: Any, assets: Path = ASSETS) -> list[str]:
    """Register the lab's tools; one already registered with the same name and version is kept."""
    existing = {(tool.name, tool.version) for tool in caliber.tools.list()}
    registered: list[str] = []
    for path in sorted((assets / "tools").glob("*.tool.json")):
        spec = json.loads(path.read_text(encoding="utf-8"))
        spec.pop("notes", None)
        name, version = spec.pop("name"), spec.pop("version")
        if (name, version) not in existing:
            caliber.tools.register(
                name,
                version=version,
                module_path=spec.pop("module_path"),
                callable_name=spec.pop("callable_name"),
                **spec,
            )
        registered.append(name)
    return registered


def setup(caliber: Any, suffix: str, assets: Path = ASSETS) -> dict[str, Any]:
    """Create the subject and return its ids and names."""
    owner = caliber.me.get().user_id
    tools = register_tools(caliber, assets)
    runs = [
        json.loads(line)
        for line in (assets / "dataset/support-runs.jsonl").read_text("utf-8").splitlines()
        if line.strip()
    ]
    gate_name = f"{NAME_PREFIX}support-policy-gate-{suffix}"
    gate = caliber.eval_datasets.create(
        gate_name, owner=owner, description="Support questions with the tools each one needs."
    )
    for row in runs:
        caliber.eval_datasets.add_example(
            gate.dataset_id,
            input={"input": row["question"]},
            expected={"expected": row["reference"], "required_tools": row["required_tools"]},
            tags=["weak" if row["weak"] else "ok"],
        )
    manifest = json.loads(
        (assets / "workflows/support-policy-agent.workflow.json").read_text(encoding="utf-8")
    )
    manifest["artifacts"]["eval_datasets"]["support_eval"]["dataset_name"] = gate_name
    workflow_name = f"{NAME_PREFIX}support-policy-agent-{suffix}"
    workflow = caliber.workflows.import_workflow(manifest=manifest, name=workflow_name)
    version = caliber.workflows.versions.list(workflow.workflow_id)[0]
    caliber.workflows.versions.publish(version.version_id)
    agent_id = f"{NAME_PREFIX}agent-{suffix}"
    caliber.agents.create(agent_id, experiment_id=f"exp-{agent_id}", name="support policy agent")
    return {
        "workflow_id": workflow.workflow_id,
        "workflow_name": workflow_name,
        "version_id": version.version_id,
        "agent_id": agent_id,
        "dataset_id": gate.dataset_id,
        "gate_name": gate_name,
        "tools": tools,
    }


def _client() -> Any:
    from caliber_sdk import CaliberClient

    base = os.environ["CALIBER_BASE_URL"]
    token = os.environ.get("CALIBER_TOKEN")
    if not token:
        import httpx

        response = httpx.post(
            f"{base.rstrip('/')}/ajax-api/2.0/mlflow/caliber/auth/login",
            json={
                "user_id": os.environ.get("CALIBER_USER", "admin"),
                "password": os.environ.get("CALIBER_PASSWORD", "admin"),
            },
            timeout=30,
        )
        response.raise_for_status()
        token = response.cookies["caliber_session"]
    return CaliberClient(base, token=token)


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__.split("\n", 1)[0])
    parser.add_argument("--suffix", default=time.strftime("%Y%m%d-%H%M%S"))
    args = parser.parse_args()
    with _client() as client:
        json.dump(setup(client, args.suffix), sys.stdout, indent=2)
        sys.stdout.write("\n")
assets/seed_traces.py 
#!/usr/bin/env python3
"""Record the 12 weak support runs as MLflow traces, so a review queue can hold them.

In a real deployment these traces are produced by your workflow and flagged by a person, a metric or
a guardrail. A fresh checkout has none, and Operate > Review Queues works on traces, so this script
writes one trace per *weak* row of ``dataset/support-runs.jsonl``: the request is the customer's
question, the response is the reply the agent gave, and the tags say which run it is
(``cookbook15.row``, S19..S30) and what went wrong (``cookbook15.failure_mode`` and
``cookbook15.reason``). The runs the agent got right are not written: nobody flags them.

Needs the ``mlflow`` package and ``MLFLOW_TRACKING_URI`` (the MLflow server CALIBER uses).
Prints a JSON map ``{"S19": "<trace_id>", ...}`` on stdout. Every run writes 12 new traces, so run
it once per environment.

    MLFLOW_TRACKING_URI=http://127.0.0.1:5000 \
      python docs-site/cookbooks/15-aria-triage-recalibrate-loop/assets/seed_traces.py > traces.json
"""

from __future__ import annotations

import json
import sys
from pathlib import Path

DATASET = Path(__file__).resolve().parent / "dataset" / "support-runs.jsonl"
EXPERIMENT = "cookbook-15-weak-support-runs"


def seed(dataset: Path = DATASET) -> dict[str, str]:
    """Write one trace per weak row and return ``{row id: trace id}``."""
    import mlflow

    mlflow.set_experiment(EXPERIMENT)
    trace_ids: dict[str, str] = {}
    for line in dataset.read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        row = json.loads(line)
        if not row["weak"]:
            continue
        with mlflow.start_span(name="support-policy-agent", span_type="CHAIN") as span:
            span.set_inputs({"question": row["question"]})
            span.set_outputs(row["reply"])
            trace_id = span.trace_id
        mlflow.set_trace_tag(trace_id, "cookbook15.row", row["id"])
        mlflow.set_trace_tag(trace_id, "cookbook15.failure_mode", row["reason"].split(":", 1)[0])
        mlflow.set_trace_tag(trace_id, "cookbook15.reason", row["reason"])
        trace_ids[row["id"]] = trace_id
    mlflow.flush_trace_async_logging()
    return trace_ids


if __name__ == "__main__":
    json.dump(seed(), sys.stdout, indent=2)
    sys.stdout.write("\n")

assets/calibrate.json 
{
  "workflow_id": "<id printed by setup_subject.py: an existing, published workflow with a deploy-gate test set>",
  "agent_id": "<id printed by setup_subject.py: a registered, enabled agent>",
  "notes": "Inputs for the Aria workflow.calibrate step (the same two fields as POST /workflows/{workflow_id}/calibration/runs {agent_id}). This is the only ASYNC capability: approving it enqueues a real refinement job and the plan PARKS in waiting_job (the plan stays running). The plan worker, or POST /aria/plans/{plan_id}/poll, resolves the job: candidate_ready or applied finishes the step (the plan completes), rejected, failed or error fails it with the job's reason. Aria passes only these two fields, so the calibration uses the default objective (maximize quality, the candidate must beat the baseline by 0.02) and the default budget (20 test set cases, 3 candidates). A workflow with no deploy-gate test set, an unknown workflow or an unregistered agent fails the step at once. Replace the placeholders with ids that exist: setup_subject.py creates a workflow and an agent for the lab."
}

Developer notes & gotchas
  • Flags and workers. CALIBER_FEATURE_ARIA=true opens /aria/* and Plans; CALIBER_FEATURE_COOKBOOKS=true is only for the gallery card. The plan worker (resumes parked plans about every 10 s) and the refinement worker (runs the job) must be on: scripts/cookbook-env.sh up lab15 --flags cookbooks,aria starts both, --no-workers does not. Export CALIBER_OPERATOR_USERS=admin,olga first.
  • Simulated calibration. The planner is rules, parking, resume and the job are real, but with the default fake providers the fake executor gives the candidate the baseline's outputs: quality delta +0.000 < epsilon 0.02, the job ends rejected and the plan failed (rejected: workflow calibration rejected: no candidate met calibration gates ...). This is expected, not a bug.
  • Completing path not shown. A job reaching candidate_ready (plan completes) needs a real model behind the executor and is covered by unit tests (caliber/tests/test_aria_async.py), not demonstrated live. The plan never applies the candidate; that is POST /jobs/{id}/apply, a person's decision.
  • Existing objects only. The traces are 12 recorded runs written by seed_traces.py; the subject is a published support workflow with a 30-case test set as its deploy gate, two tools and an agent. The enqueue step does not check that trace ids exist; calibration needs a visible workflow, a registered agent and a deploy-gate test set with rows.
  • Planner limits. workflow plans a calibration whatever the sentence means ("create a new workflow", "roll back", "outage"); "pipeline" and "tune" plan nothing; negation is not read; there is no add-to-existing-queue step, so a queue is created first.
  • Queue visibility. A queue created outside a workspace is visible to its owner only; reviewers is a label (lab 13). The workflow's own runs do not write traces on this stack.
  • Run it. PYTHONPATH=sdk/caliber-sdk caliber/.venv/bin/python -m examples.cookbooks.cookbook_15_aria_triage_recalibrate_loop (example: sdk/caliber-sdk/examples/cookbooks/cookbook_15_aria_triage_recalibrate_loop.py); the first UI test takes about a minute and a half.
