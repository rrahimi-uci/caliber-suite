Cookbook 16 · Operate

Production Observability & Triage

Turn real production traces into a regression test set and a triage review queue, with the reviewers' answers written back onto the traces.

OperateCore30–45 min
What you build. You replay 40 production-like refund tickets through a real workflow (the buggy version 1 of cookbook 09), so CALIBER records 40 MLflow traces: 12 ERROR and 28 OK, four of which are silently wrong. You find failures with the status filter, read a trace's node tree for the failing node, capture the 16 traces that matter into a test set with their gold outcome, and route them to a prod-triage review queue whose answers appear as assessments on the traces. Nothing here needs a model.
Surfaces: Observability Test Sets Review Queues Workflows
What you learn
  • Filter traces by status (All statuses / OK / Error / In progress) and search by text
  • Read the Spans tree: node.validate, node.check_reference or node.decide is ERROR; for an upstream failure node.lookup is OK and decide fails
  • Capture traces into a test set with Add to test set or Capture from trace, then replace the captured error text with the gold outcome
  • Stand up a review queue with five triage questions, enqueue trace ids and submit reviews so answers write back as trace assessments
  • See how Observability behaves on an unknown trace (404), no match (empty list) and MLflow down (503)
  • Find the 4 silent failures (P25 to P28) that the Error filter cannot see

assets/seed_traces.py 
#!/usr/bin/env python3
"""Run the lab's 40 production tickets through a real workflow, so Observability has real traces.

In production these traces come from your own traffic. A fresh stack has none, and every step of this
lab works on traces, so this script produces them the way production does: it imports the
``refund-intake`` workflow from cookbook 09 (version 1, the one with the bugs), publishes it, and
submits each ticket in ``dataset/prod-regression.sample.jsonl`` as a workflow run. CALIBER's runtime
records an MLflow trace for every run; nothing here writes a trace itself, and no row is fabricated.
Which runs fail is decided by the workflow, not by this script.

Needs a server that can reach cookbook 09's stand-in account service (port 8780) and was started with
``CALIBER_EGRESS_ALLOWED_HOSTS=127.0.0.1``. Prints a JSON map ``{"P01": {"run_id", "trace_id",
"status"}, ...}`` on stdout. Every call imports a new workflow and writes 40 new traces, so run it once
per environment.

    export CALIBER_BASE_URL=http://127.0.0.1:5001 CALIBER_TOKEN=calpat_...
    PYTHONPATH=sdk/caliber-sdk python \
      docs-site/cookbooks/16-observability-triage/assets/seed_traces.py > traces.json
"""

from __future__ import annotations

import json
import os
import sys
import time
from pathlib import Path
from typing import Any

HERE = Path(__file__).resolve().parent
DATASET = HERE / "dataset" / "prod-regression.sample.jsonl"
#: Cookbook 09's version 1: validate, check_reference, lookup, decide.
WORKFLOW = (
    HERE.parents[1]
    / "09-workflow-debugger-self-healing-lab/assets/workflow/ticket-intake.v1.workflow.yaml"
)
RUN_TIMEOUT_SECONDS = 180.0


def load_rows(dataset: Path = DATASET) -> list[dict[str, Any]]:
    lines = dataset.read_text(encoding="utf-8").splitlines()
    return [json.loads(line) for line in lines if line.strip()]


def seed(
    caliber: Any,
    *,
    rows: list[dict[str, Any]] | None = None,
    suffix: str | None = None,
    workflow_file: Path = WORKFLOW,
) -> dict[str, dict[str, str]]:
    """Import and publish the workflow, run every row through it, return what each run produced."""
    rows = rows if rows is not None else load_rows()
    suffix = suffix or str(int(time.time()))
    workflow = caliber.workflows.import_workflow(
        manifest_yaml=workflow_file.read_text(encoding="utf-8"),
        name=f"prod-refund-intake-{suffix}",
    )
    version = caliber.workflows.versions.publish(
        caliber.workflows.versions.list(workflow.workflow_id)[0].version_id
    )
    submitted = {
        row["id"]: caliber.workflows.runs.submit(
            workflow_version_id=version.version_id, input=row["input"]["payload"]
        )
        for row in rows
    }
    seeded: dict[str, dict[str, str]] = {}
    for row_id, run in submitted.items():
        done = caliber.workflows.runs.wait(
            run.workflow_run_id, timeout=RUN_TIMEOUT_SECONDS, raise_on_failure=False
        )
        seeded[row_id] = {
            "run_id": done.workflow_run_id,
            "trace_id": done.trace_id or "",
            "status": done.status,
            "workflow_id": workflow.workflow_id,
        }
    return seeded


if __name__ == "__main__":
    from caliber_sdk import CaliberClient

    with CaliberClient(
        os.environ["CALIBER_BASE_URL"], token=os.environ["CALIBER_TOKEN"]
    ) as client:
        json.dump(seed(client), sys.stdout, indent=2)
    sys.stdout.write("\n")

Evaluation & quality gates

Quality gateTarget
Traffic recorded40 new traces, 12 ERROR and 28 OK, and the Error filter finds every failing one
Root cause readablethe failing node (validate, check_reference or decide) is ERROR in the node tree
Failure pathsunknown trace id 404, empty window empty list, MLflow down 503
Test set16 traces (12 errors + 4 wrong OK ones), each with its gold outcome
Triage written backprod-triage holds the same 16, two answered, and their five answers appear as assessments
Developer notes & gotchas
  • Feature flag. The lab needs none (Observability, Test Sets and Review Queues are supported alpha); CALIBER_FEATURE_COOKBOOKS=true only opens the gallery. Aria is not used.
  • Setup. The traces come from cookbook 09's workflow: run the stand-in account service (account_service.py 8780, not a real system) and start the server with CALIBER_EGRESS_ALLOWED_HOSTS=127.0.0.1, otherwise all 40 seed runs fail. A worker is required.
  • Nothing is simulated, no model needed. The workflow has no agent node, so the fake default providers change nothing. The optional Evaluations baseline on the test set is not part of this lab (Evaluations refuse on a simulated stack, see lab 10).
  • A capture stores the trace's response as the expected answer, which for a failed run is the error text; edit the example (or pass expected in the API) to put the gold outcome on it.
  • MLflow records traces asynchronously, so the last trace of a run can read IN_PROGRESS for a moment. With CALIBER_TRACING_ENABLED=false runs complete but trace_id is null.
  • Alpha limit: traces are not scoped to a project, so any signed-in user can read every trace and its request text; do not put sensitive data in them on a shared deployment.
  • Not covered: trace-to-refinement automation, the Evaluations baseline, and the UI rendering of the MLflow-down 503 (checked through the API only).
